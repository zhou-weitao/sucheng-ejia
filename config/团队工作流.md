# 🏢 苏城e教团队开发工作流

## 📋 角色分工

| 角色 | 职责 | 对应Skill |
|------|------|-----------|
| **产品负责人（PO）** | 需求分析、PRD编写、优先级排序、验收标准 | agile-product-owner |
| **项目经理（PM）** | 项目规划、进度跟踪、风险管理、资源分配 | senior-pm |
| **Scrum Master** | 敏捷流程、冲刺管理、团队协调、回顾改进 | scrum-master |
| **代码项目经理** | 代码审查、质量门禁、任务分发 | coding-pm |
| **前端开发** | 微信小程序前端开发 | - |
| **后端开发** | 云函数/后端服务开发 | - |
| **测试工程师** | 功能测试、集成测试、性能测试 | - |

## 🔄 敏捷开发流程

### 1️⃣ Sprint 0：项目启动（1周）

**输出产物：**
- `docs/plans/项目章程.md`
- `docs/prd/产品需求文档v1.0.md`
- `docs/plans/技术选型方案.md`
- `docs/plans/项目里程碑.md`

**执行步骤：**
```
1. 产品负责人编写PRD
   └─ 调用：agile-product-owner → 用户故事模板
2. 项目经理制定项目计划
   └─ 调用：senior-pm → 风险分析 + 资源规划
3. 技术团队评审技术方案
4. 团队确认开发环境配置
```

### 2️⃣ Sprint 1-N：迭代开发（每2周）

#### Sprint 规划会议（2小时）
```
1. Scrum Master主持
2. 产品负责人讲解优先级最高的用户故事
3. 团队估算故事点（斐波那契：1,2,3,5,8,13）
4. 确认Sprint目标和交付物
5. 输出：docs/sprints/sprint-X计划.md
```

#### 每日站会（15分钟）
```
每个团队成员回答：
1. 昨天完成了什么？
2. 今天计划做什么？
3. 遇到了什么阻碍？

Scrum Master记录：
- docs/meetings/standup-YYYYMMDD.md
- 阻塞问题跟踪和解决
```

#### Sprint 评审会议（1小时）
```
1. 演示本次Sprint完成的功能
2. 收集利益相关者反馈
3. 产品负责人确认验收
4. 更新产品待办列表
```

#### Sprint 回顾会议（1小时）
```
使用 Start-Stop-Continue 模式：
1. 开始做什么（Start）
2. 停止做什么（Stop）
3. 继续做什么（Continue）

输出：docs/sprints/sprint-X回顾.md
```

## 📝 文档规范

### PRD文档结构（`docs/prd/`）
```markdown
# 产品需求文档

## 1. 需求背景
## 2. 用户故事
   - 作为 [角色]
   - 我想要 [功能]
   - 以便 [价值]
## 3. 功能描述
## 4. 验收标准（Given-When-Then）
## 5. 优先级和依赖
## 6. 非功能需求
```

### Sprint计划结构（`docs/sprints/`）
```markdown
# Sprint X 计划

## Sprint目标
## 待办列表（用户故事+故事点）
## 团队容量
## 风险和依赖
## 里程碑
```

## ✅ 代码质量门禁

### 提交前检查
```
✅ 代码编译通过
✅ 单元测试通过
✅ ESLint代码规范检查
✅ 代码审查（至少1人批准）
```

### 合并到主干标准
```
✅ 功能完整实现
✅ 验收测试通过
✅ 文档同步更新
✅ 产品负责人确认验收
```

### 发布标准
```
✅ 所有P0/P1 Bug修复
✅ 性能指标达标
✅ 安全扫描通过
✅ 回归测试通过
```
